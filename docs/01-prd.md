# 01 产品需求文档（PRD）

## 1. 背景与目标

企业内部知识散落在 PDF、Word、Excel、Wiki 等载体中，员工检索成本高、口径不一致。本项目构建企业级知识库，目标：

1. **统一沉淀**：多格式文档统一解析、切片、入库，按知识空间隔离管理
2. **精准问答**：Agentic RAG 架构，简单问题秒回，复杂业务问题通过知识图谱多跳推理给出带引用的答案
3. **安全可控**：文档级权限管控，问答全程审计，支持私有化部署
4. **可持续运营**：全链路可观测（LangFuse），答案质量可评估、可迭代

## 2. 用户角色

| 角色 | 职责 | 关键权限 |
| --- | --- | --- |
| 系统管理员 | 系统配置、模型接入、用户与空间管理、审计查看 | 全部 |
| 知识管理员 | 在空间内上传/下架文档、重建索引、维护图谱实体 | 空间内 Owner/Editor |
| 普通员工 | 浏览有权限的空间、提问、查看引用原文、反馈答案质量 | 空间内 Viewer |

## 3. 核心使用场景

### 3.1 文档入库（知识管理员）
上传文件 → MinerU 解析（版面/表格/公式）→ 语义分块 → Embedding → 双写 PGVector 与 ES → 实体抽取写入 Neo4j → 状态变为「可检索」。全过程异步，可查看进度与失败原因。

### 3.2 简单问题问答（员工）
> 「差旅报销的住宿标准是多少？」

Agent 判定为简单问题 → 混合检索（ES + PGVector）→ RRF 融合 → Reranker → 权限过滤 → 拼接记忆与分片 → LLM 流式生成，附引用分片，点击可跳转原文位置。

### 3.3 复杂业务问题（员工）
> 「A 项目的供应商同时服务了哪些其他项目？这些项目的负责人分别是谁？」

Agent 判定为复杂问题 → 额外触发图谱链路：LLM 抽取实体（A 项目、供应商）→ Neo4j 多跳查询（项目-供应商-项目-负责人）→ 推理链路与检索分片一并进入上下文 → 生成结构化答案并展示推理路径。

### 3.4 多轮追问（员工）
> 先问「A 项目预算多少」，再问「那 B 项目呢」

Redis 滑动窗口保存近期对话摘要，Mem0 提供用户长期偏好/历史关注点，指代消解后改写为完整问题再进入检索流程。

### 3.5 语音问答（可选，员工）
开启语音后，SSE 文字流的同时，TTS 服务将答案分句合成语音，经 WebSocket 推送前端同步播放。

### 3.6 权限管控（管理员）
按空间授权用户/角色；用户权限白名单缓存在 Redis，问答时先校验，检索结果再做分片级过滤，双重保障。

## 5. 非功能需求

| 类别 | 指标 |
| --- | --- |
| 性能 | 检索+重排 ≤ 800ms（P95）；首 Token ≤ 2.5s（P95，简单问题）；图谱多跳 ≤ 1.5s（P95） |
| 并发 | 单实例支持 50 并发问答；Worker 解析吞吐 ≥ 5 页/秒（CPU 模式） |
| 可用性 | 核心问答链路 99.5%；MinerU/Neo4j/TTS 故障时降级（跳过对应增强步骤，不阻断主流程） |
| 安全 | 传输 TLS；敏感配置 KMS/环境变量注入；越权访问零容忍（检索前置过滤） |
| 可观测 | 100% 问答请求生成 LangFuse Trace；慢查询与异常自动告警 |
| 可扩展 | LLM/Embedding/Reranker/TTS 均为 OpenAI 兼容或 HTTP 抽象，可替换供应商 |

## 6. 边界与约束

- 一期不做人人在线协同编辑（以文档快照管理为主）
- 图谱构建以「入库时自动实体抽取」为主，人工维护台为 P2
- MinerU 为 Python 独立服务，GPU 可选（CPU 可运行，速度下降）
- 所有外部模型调用走内网 LLM 网关，禁止前端直连
